# Venture app conventions

This repo holds several independent web apps, one folder each (`rewater/`, …). Each app deploys on its own
(Vercel, Root Directory = the folder). Keep them consistent so work on one transfers to the others.

## Stack (pinned on purpose)

| Piece | Version | Why pinned |
|---|---|---|
| Next.js (App Router) | 16.4.x | Current major. |
| React / React DOM | 19.3.x | |
| TypeScript | **5.9.x** | `npm i -D typescript` pulls 7.x (the native port), which Next's build does not support yet. Always `typescript@5.9.3`. |
| Tailwind CSS | 4.x via `@tailwindcss/postcss` | CSS-first config: tokens live in `globals.css`. |
| Vitest | 5.x | Config file must be `vitest.config.mts` (a `.ts` config prints an ESM warning). |

No other runtime dependencies unless they earn it. Charts are hand-built SVG (see below). Use `new-venture-app`
to scaffold a new app with all of this already set.

## Layout inside an app

```
src/app/            routes (page.tsx per route), layout.tsx, globals.css, icon.svg
src/components/     React components; charts/ for chart primitives
src/lib/            pure logic. The core of each product lives here, framework-free and unit-tested.
src/lib/**/X.test.ts  tests next to the code
src/config/site.ts  name, tagline, contact. Empty contact = hide the button, never a fake address.
README.md           what works, how to run, how to deploy, where to take it next
```

Put the product's real logic (verification, scoring, matching…) in `src/lib/` as pure functions with tests.
UI calls it. That keeps it portable to an API or a worker later.

## Design tokens and dark mode

- Colors are CSS custom properties on `:root` in `globals.css`, redefined for dark mode under
  `@media (prefers-color-scheme: dark)` guarded by `:root:where(:not([data-theme="light"]))`, and again under
  `:root[data-theme="dark"]`. They are exposed to Tailwind via `@theme inline` (`bg-surface`, `text-ink-2`, …).
- Use token classes (`bg-surface`, `text-ink`, `text-ink-2`, `text-muted`, `border-line`, `bg-brand`), never raw hex in components.
- System font stack. One brand accent per app; everything else is ink and surface.
- Every page must work at 390px wide with no horizontal scroll. Grid/flex children that hold charts or wide tables
  need `min-w-0`; wide tables go inside `overflow-auto`.

## Charts

- Load the `dataviz` skill before writing chart code, and run its palette validator on any new series colors.
- Reuse `rewater/src/components/charts/` (LineChart, ColumnChart, scale, useWidth) by copying it into the new app.
  They already follow the spec: 2px lines, ≤24px bars with a rounded data-end, hairline grid, legend for ≥2 series,
  crosshair tooltip, keyboard focus, and a "Show data table" view.
- Axis ticks must be short (no units) so they fit the 52px left margin. Put the unit in the title.
- Never a dual-axis chart. Shared y-domain across small multiples.

## Data honesty (non-negotiable)

- Demo data is generated by a seeded function in `src/lib/` and **labeled as simulated everywhere it appears**
  (the button, the report header, the footer). Never present simulated numbers as real.
- Never invent statistics, quotes, customers, logos or testimonials. A market claim on a page gets a source link,
  or it does not go on the page.
- Phrase competitive claims as what we found ("we found no one doing X"), not as facts about the world.
- Report the conservative number as the headline when a number will be sold or relied on.

## Privacy and safety

- Prefer processing user files in the browser. Say so on the page only if it is true.
- Anything involving minors (students, young athletes): collect the minimum, no public profiles by default,
  the student controls sharing, never sell or share data with third parties for marketing. Student privacy laws
  (FERPA, COPPA, California SOPIPA) and the College Board settlement are the reason.
- No real person's or business's name or phone number on a publicly reachable page without their consent.
- Secrets never go in the repo. Config that needs a secret reads `process.env` and the app works without it.

## Known pitfalls

- `pkill -f "<pattern>"` kills your own shell if the pattern appears in the command. Use the `ship-check`
  `serve.sh`, which stops servers by their working directory.
- `next start` runs the server as a child process; killing the wrapper PID leaves the old server bound to the port,
  serving a stale build whose JS chunks 500 after a rebuild. Symptom: buttons do nothing.
- Playwright: wait ~1s after `networkidle` before clicking, or the click lands before hydration.
- `next build` rewrites `tsconfig.json` (`jsx: react-jsx`, extra include). Commit that change; it is expected.
